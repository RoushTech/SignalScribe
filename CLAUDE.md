# SignalScribe — Project Rules

## Project Structure

```
SignalScribe/           Class library — entities, enums, SignalScribeContext, shared contracts
SignalScribe.Api/       ASP.NET Core web host — single DB writer, job-queue API, serves frontend
SignalScribe.Capture/   Capture daemon — SDRPlay/IQ-replay sources, PFB channelizer, demod, Opus clips
SignalScribe.Modem/     Soft TNC — AFSK/HDLC/AX.25. **MIT, not GPL** — see its own LICENSE/README
SignalScribe.Workers/   Processing workers — transcription, embeddings, net analysis, summaries
SignalScribe.Vue/       Vue 3 / Vite frontend (dev server runs separately)
SignalScribe.Tests/     Tests (incl. IQ-replay DSP regression)
```

## Running the Project

**Web host** (from repo root):
```bash
dotnet run --project SignalScribe.Api
# http://localhost:5020
```

**Capture daemon / workers** (from repo root):
```bash
dotnet run --project SignalScribe.Capture
dotnet run --project SignalScribe.Workers
```

**Frontend** (from `SignalScribe.Vue/`):
```bash
npm run dev
```

**Docker** (from repo root):
```bash
scripts/fetch-sdrplay-api.sh   # once per checkout — populates vendor/sdrplay (proprietary, gitignored)
docker compose up --build
# One image, three services: api, workers, capture. Only `api` mounts the DB
# volume (single-writer, filesystem-enforced). Models go in the `models`
# volume via scripts/download-models.sh — never into the image.
# capture: runs sdrplay_apiService in its entrypoint; USB passes through via the
# /dev/bus/usb bind mount + cgroup rule 189:* (survives unplug/replug).
```

**Known tooling wart:** `dotnet ef` on Linux leaves literal `bin\Debug` directories (backslash in the
name). They break MSBuild resource globs with MSB3552 locally and in Docker builds. `.gitignore` and
`.dockerignore` exclude them; if a build hits MSB3552, run `find . -name '*\\*' -not -path './.git/*' -prune -exec rm -rf {} +`

**EF Core migrations** (from repo root):
```bash
dotnet ef migrations add <Name> \
    --project SignalScribe/SignalScribe.csproj \
    --startup-project SignalScribe.Api/SignalScribe.Api.csproj

dotnet ef migrations remove \
    --project SignalScribe/SignalScribe.csproj \
    --startup-project SignalScribe.Api/SignalScribe.Api.csproj
```

## Stack rules

- **C#/.NET everywhere.** No Python at runtime. ML/inference goes through .NET bindings to native libraries (Whisper.net, LLamaSharp, ONNX Runtime, Concentus). Don't propose other-language components unless there is no viable .NET path — and say why.
- **Fully offline.** No cloud APIs, no Claude/OpenAI, no telemetry. Everything must work with the network unplugged after model download.
- **Every gate records from before the carrier was noticed.** The gate deliberately waits two blocks (~20 ms) for a carrier to persist, which is what keeps clicks and splatter out — and the price is that the opening moment of every transmission was already gone by the time recording started. On analog that was the clipped first syllable; on D-STAR it was the entire header, over within ~25 ms, and with it the callsigns. `ChannelBank` therefore keeps a ring of whole channelizer frames (`PreRollSeconds`, 150 ms) and replays the channel's recent past into a newly opened gate. Three things follow and must be kept true: the clip's `StartUtc` and filename come from the **pre-roll start**, not the gate hop, or every clip lies about when it began; `GateOpenedHop` still comes from the gate, so the max-open valve and clip rollover are not fooled into thinking a transmission is older than it is; and the replay reports `SignalPresent = false`, so pre-roll noise cannot pad the signal-present time that the too-short test depends on, nor pollute the carrier-offset average and mode histogram — while the decoders, which are not squelch-gated, get exactly what they were missing. A rollover is a continuation and replays nothing, or it would duplicate audio it just wrote.
- **D-STAR gives callsigns without a vocoder, and the CRC is what makes them trustworthy.** The header carries MYCALL/URCALL/RPT1/RPT2 in plain ASCII, so `DStarFramer` + `DStarHeaderFec` recover who is calling whom with no AMBE anywhere near it. Because a 16-bit CRC gates every header, sync detection can afford to be generous — two wrong sync bits tolerated, and both discriminator polarities tried, since which way a one comes out depends on the receiver's mixing and nothing upstream pins it. A false sync costs one Viterbi decode that then fails; being strict instead would lose marginal headers and could never manufacture one. That generosity is safe *only* behind a CRC. Naming a transmission D-STAR without a decoded header — the marginal-signal case the voice-frame sync exists for — must instead demand the **420 ms cadence**: syncs spaced multiples of 2016 symbols apart, in one polarity. A raw count can never be the verdict, because the 24-bit sync at two errors' tolerance in both polarities trips about every six seconds on noise-shaped input, and squelch tails, repeater hang and pre-roll feed the framer exactly that — measured, a plain FM ragchew accumulated three hits, was named D-STAR, and was silently excluded from transcription. The C4FM detector's "repetition stands in for proof" reasoning does not transfer to a 24-bit word: its own words are 48 bits at ≤3 errors, five orders of magnitude tighter per symbol.
- **Header data belongs to every digital mode, not to D-STAR.** Every digital voice mode sends identity and routing in an FEC-protected channel *beside* the vocoder, so `DecodedHeader` is shaped around ordered name/value fields rather than any one protocol: a framer reports whatever its mode carries, and ingest, storage, the API and the UI carry all of it without a per-mode branch. Adding a mode costs a framer and nothing else. Report the **whole** header, not a summary — on a mode whose voice needs a vocoder we do not have, those fields are the entire content of the transmission, so dropping the ones we cannot yet interpret (D-STAR's raw flag bytes) throws away the only thing that arrived intact. `Segment.HeaderModel(mode)` generates the model name and reproduces the pre-existing `signalscribe/dstar-header` exactly, so old rows stay valid.
- **A CRC proves the bits arrived; it cannot prove what they mean.** Fusion's FICH is CRC-16 protected, and that CRC covers the 32 data bits *whatever layout is imposed on them* — so a wrong field mapping passes the CRC and displays a confidently wrong call type. Interpreted FICH fields therefore stay behind `YsfFich.LayoutConfirmed` until a live signal has proved the layout by showing the frame counter actually counting up to its total and wrapping; until then the operator gets the raw CRC-verified bytes, which is the honest record and costs no migration to reinterpret later.
- **Where a protocol's conventions are unpublished, search them and let the CRC decide.** The Fusion FICH chain is documented (deinterleave 5×20, Viterbi K=5 rate 1/2, four Golay(24,12) blocks, CRC-16 0x1021) but the conventions *inside* it are not: interleaver read order, which generator polynomial goes first, which half of a Golay block is systematic, CRC seed and byte order. Each is self-consistent when wrong, so a guess yields a decoder that is silent rather than incorrect — indistinguishable from no traffic. `YsfFichVariant` therefore enumerates all 192 combinations and tries every one per frame, exactly as `DStarFramer` searches polarity, requiring `MinFrames` CRC-valid frames from the *same* variant before reporting (that many variants against a 16-bit CRC pass on noise often enough to see — measured, one accidental pass per 12,800 tries). This is a calibration expense — 10% of a core on a live carrier — so the framer narrows to the settled variant immediately, dropping to 0.2%; `YsfCostTests` guards that narrowing, and once air has named the variant it should be pinned and the search retired.
- **An all-zero frame is not a frame.** A zero-seeded CRC over zero data is zero, so a dead field satisfies it with no signal behind it — a fade driving every soft bit to a constant, or a decoder reading the half of a Golay block that carries no data. `YsfFichDecoder` rejects it outright; this was found because a test fixture left the parity half blank and eight wrong variants "decoded" it.
- **A digital framer does its own DC and level tracking.** The demodulator's carrier EWMA has a 200 ms time constant, tuned for holding voice steady — and a D-STAR header is over in 190 ms, so it is still crawling. The residual offset lands straight on the slicer, and for a two-level decision a DC bias *is* the error: a carrier 2.5 kHz off its bin decoded nothing until the framer tracked its own. It acquires as a true mean and eases into an EWMA, because a plain EWMA is only ~78% converged by the end of the bit-sync preamble and a DC estimate still moving when the frame sync arrives loses the sync outright.
- **The open D-STAR header decoders are GPLv2-only — do not port them.** Every implementation in circulation (DSD, DSDcc, MMDVMHost) traces to one file by G4KLX carrying a "version 2 of the License" notice with no "or later", which is **incompatible with GPLv3**. DSDcc ships it unchanged despite being v3 itself; that is DSDcc's problem and grants us nothing. `DStarHeaderFec` is therefore written from the protocol rather than ported: the convolutional polynomials, CRC and frame sync are published facts, the scrambler is generated from x⁷+x⁴+1 rather than lifted as a table, and the interleave is the specification's own permutation that any conforming decoder must reproduce to interoperate. GopherTrunk (Apache-2.0) documents the chain usefully but flags its own scrambler and interleaver as uncalibrated, so it is a reference for structure, not for tables.
- **GPLv3, so mind where code comes from.** The project is GPLv3 (`LICENSE`) with an SDRplay linking exception (`COPYING.exception`) — the vendor API is proprietary and the exception is what keeps binaries distributable. Porting *from* GPL projects (SDRTrunk, DSDcc, OP25, JMBE, multimon-ng) is therefore fine and is the point of the choice; record the upstream project and licence in a header comment on every ported file. Permissive upstreams (DSD-FME and mbelib are ISC, GopherTrunk Apache-2.0) are preferable where equally good, since those files stay reusable. `SignalScribe.Modem/` is deliberately **MIT** — it is vendored from the operator's own MIT DireControl and kept permissive so fixes can flow back; never copy GPL code into it. Never vendor `md380_vocoder` (extracted firmware, unlicensed) or `openear` (no published source).
- **Never edit an applied migration.** Once a migration is in a database's `__EFMigrationsHistory`, changing its file — including its seed `HasData`, its Designer, or the model snapshot — cannot be picked up by that database. The only way to converge is to drop the data and re-migrate, so every such edit costs the operator their recordings. Model or seed changes get a **new** migration, always. The sole exception is squashing, which is a deliberate reset the operator has asked for; do the whole squash in one pass, and once it is applied it is frozen like any other.
- **EF Core, never bare SQLite.** All schema changes go through EF migrations. The FTS5 virtual table is created with `migrationBuilder.Sql()` inside a normal migration (the bundled native provider has FTS5 compiled in) and queried via an FTS-mapped keyless entity + `FromSql` interpolated `MATCH`, composed with LINQ. No `SqliteConnection` used directly outside the EF provider (in-memory test connections excepted — see Testing).

## Architecture invariants

- **Single writer.** Only the web host touches the database. Capture daemon and workers talk to it over HTTP. Workers claim jobs with lease semantics; completions are idempotent.
- **Capture never blocks.** The capture daemon writes audio to disk itself and spools metadata events to a local append-only journal when the host is unreachable, replaying on reconnect. Audio is never streamed over HTTP — metadata carries file paths.
- **Channels auto-create on voice or on a named mode, not on squelch.** A transmission on an unknown frequency must either pass the capture-side voice-likeness gate (syllabic 2–8 Hz envelope modulation + speech-band energy + min duration) or be a modulation `ModeClassifier` can *name*, before it is posted and the channel row springs into existence; anything else on an unknown frequency is dropped. Naming the mode is the same kind of evidence as sounding like voice — it says what the frequency is. Known channels record everything their squelch opens — but that trust is revocable: a channel with `ChannelVoiceAudit.MinResolvedRecordings` settled recordings and no speech in any of them is auto-disabled (`Channel.AutoDisabledReason`), dropping out of the daemon's known set so its traffic must pass the gate again. A channel whose mode *is* known is exempt from that audit: it is understood, and a digital voice channel produces no transcript today only because its vocoder is not wired up yet. The first real transcript re-enables an auto-disabled channel. The worker-side VAD remains the authoritative voice check before transcription. A learned digital-voice mode is revocable by the same proof: it silences transcription and exempts the channel from the audit, and analog FM — deliberately not an *identified* mode — can never overwrite it, so a false one would stick forever. A real transcript on the channel therefore demotes it (`LearnedModeDemotion`) and re-queues the channel's untranscribed digital-voice transmissions that never decoded a header; ones with a CRC-valid header keep their mode, because the CRC vouched for those and a transcript elsewhere cannot unsay it.
- **APRS is identified by decoding it, not by measuring it.** `SignalScribe.Modem` is a soft TNC — AFSK demodulator, HDLC deframer, AX.25 decoder — and a CRC-valid frame out of it is proof where the level histogram only ever offers evidence, so a decoded packet overrides `ModeClassifier` outright. It taps the **discriminator, not the 16 kHz audio**: measured, a packet decodes from the audio path only while the carrier sits within ~2 kHz of its filterbank bin, and 144.390 sits 2.5 kHz off the 12.5 kHz grid — off the discriminator it decodes across the whole ±5 kHz the grid allows. De-emphasis alone tilts Bell 202's two tones by ~6 dB, which is what the per-tone AGC exists to undo. Decoded frames become `Segment` rows carrying TNC2 text and `Segment.PacketDecoderModel`, so they inherit FTS search and every list view — but they must never be counted as speech (see the channel audit), and they are deliberately **not** routed through `IngestTranscript`, which stamps `LastSpeechUtc` and re-enables the channel.
- **The raw frame is the record; the human reading is derived.** `Segment.Transcript` holds the TNC2 line exactly as decoded, and `AprsSummary.Describe` (AprsSharp) renders it into something readable — position, weather figures, message text — on the way out in `TransmissionMapper`, never stored. That way improving the reading costs no migration and applies retroactively to traffic already captured, and a frame the parser cannot handle simply shows its raw form rather than blocking ingest. The APRS information field is loose and much abused, so `Describe` returns null rather than throwing or guessing.
- **The soft TNC is rationed; the tone and mode detectors are not.** CTCSS costs ~0.1% of a core per open gate and mode classification ~0.02%, so both run on every gate unconditionally. The packet decoder costs ~4% — forty times as much — and on all 32 gates would want one and a half cores on top of the channelizer's 70%, which capture cannot afford without falling behind the sample stream. So `ChannelBank.MaxPacketDecoders` caps it, and `ShouldDecodePackets` spends it only where it can change the answer: an **unknown frequency** (where a packet is otherwise discarded as not-speech and the frequency stays invisible) or a channel already understood to carry **data** (or it would go quiet the moment decoding made it known). A known analog voice repeater is excluded, giving up the mismatch case the tone detector runs everywhere to catch — the free `ModeClassifier` still watches every gate, so a repeater that starts carrying data still shows up.
- **"Some kind of digital" is not an identification.** `DetectedMode.DigitalUnknown` deliberately does not earn a channel (`DetectedModeExtensions.IsIdentified`). An APRS burst reads as an anonymous two-level signal until the soft-TNC decodes a CRC-valid frame, and admitting it on level structure alone would put 144.390 straight back to recording every packet forever — the exact failure `ChannelVoiceAudit` was written to undo. Such clips are discarded as `DiscardReason.DigitalNotIdentified`, which tells the operator what was actually there instead of blaming the speech band.
- **Modulation is measured from levels; the mode is named by its sync pattern.** `ModeClassifier` histograms the discriminator's deviation, because a digital signal dwells at a few discrete levels and speech does not. That reliably separates analog from digital, and separates the two-level modes from each other (D-STAR's ±1.2 kHz and POCSAG's ±4.5 kHz are nearly four times apart). It deliberately refuses to name a *four-level* mode: DMR's ±1944/±648 plan and the ±1800/±600 shared by P25, YSF and NXDN96 are only 8% apart, while the channel filter alone compresses the outer symbols 4% on a bin centre and 6% at 2.5 kHz off it (`DigitalModeDiag`), and ordinary transmitter deviation error is the same order again. Any threshold there would be reporting the carrier's grid alignment as much as its modulation. Sync patterns settle it, and belong to the framers.
- **The classifier reads the discriminator, and only after the DC tracker has settled.** It taps `freqHz` ahead of de-emphasis and the soft limiter — both exist to make speech pleasant and destroy the level structure — and one stage earlier than `SubaudibleDetector`. It is fed only while squelch says signal is present, because the tail is noise averaging to zero which fills the middle of the histogram. It also discards the first `ModeClassifier.WarmupSeconds`: the demodulator's DC EWMA is seeded from whichever symbol was transmitting when the gate opened and crawls toward the carrier over ~600 ms, offsetting every sample along the way by a different decaying amount. That does not shift the histogram, it smears it — measured, it turned four clean levels into one hump and classified DMR as analog.
- **A Whisper run costs the same whether it carries one second of audio or thirty.** Whisper pads every run to a 30-second mel window, so cost is per *run*, not per second — measured on air, ~7 s of wall time either way, and a 1.1 s clip cost 7.4 s while a 7.6 s clip cost 7.2 s. Two things follow. Every clip queued that cannot contain speech wastes a **whole** run: an APRS burst that failed its CRC reads as `AnalogFm`, clears the voiced-audio bar on its own hiss, and buys a full run that can only hallucinate — measured, 34 of 72 posted transmissions on 144.390 fell through that way, so `TranscriptionGate` declines anything on a channel *understood* to carry data (pinned `Modulation` first, then learned), and that pin is the escape hatch keeping a wrong label from silencing a voice channel forever. And running a lone clip the instant it arrives spends a run on a nearly empty window: `SpeechPacker` already packs spans into one 27 s window and attributes the results back by timestamp, but it can only pack what it is handed, so `BatchGather` keeps the poller claiming until the window is full or the operator's latency budget expires. Anything the gate declines must read as finished, never "processing" — a pending state that never resolves is worse than the wasted run it replaced.
- **One segment row per over.** Transcription splits a clip at the capture-side boundary markers (`ClipSplitter`) and runs the model on each span independently — handing a whole multi-over clip to Whisper loses everything after the first over, because it treats the inter-over gap as end-of-speech. A `Segment` is therefore one station's over: the unit speaker embedding and clustering need. Never split segments on the model's sentence breaks; those are punctuation, not speaker changes.
- **A double is a heterodyne, not any steady tone.** `IsDouble` and the `HeterodyneDouble` marker come from a sustained tone **inside** 300–2700 Hz — two carriers on one channel beat into an audible whistle there. Hum, leaked CTCSS and buzz sit below the band; flagging those as doubles suppresses transcription on perfectly readable audio (observed on 146.925). Out-of-band tones produce no marker at all: a hum is not a courtesy tone and must never split a clip into overs.
- **A tone under the voice is not a tone instead of the voice.** Real transmissions carry hum, leaked CTCSS, link tones and buzz, and the tone is audible in the *gaps between words* — so every pause reads as a pure tone. A sustained tone therefore only disqualifies speech when it lies **inside** the 300–2700 Hz voice band, where it could be mistaken for speech; one outside it is something the speech sits on top of. A dominant narrowband peak outside that band is also subtracted before judging speech-band dominance, and the envelope that drives the syllable test is high-passed at 300 Hz — measured broadband, a steady tone raises the floor and flattens the very variance the test looks for (observed on 147.180: 13 s of a man talking scored 0.15 speech ratio, 864 ms voiced, 0.10 modulation depth).
- **Squelch gates recording, not segmentation.** Transmission boundaries are separate marker events (repeater squelch crash, courtesy tone, RF edges, discriminator DC-offset jumps), refined downstream by within-clip speaker-embedding splits. Never assume one squelch-open == one speaker (quick-keying; repeater tails keep the carrier up).
- **ADC overload means go quiet, not go deaf.** The SDRplay API reports front-end overload as a start/stop pair (`sdrplay_api_PowerOverloadChange`, with the change type in the first field of the event-params union). While overloaded the ADC is clipping and every bin carries compression products instead of signal, so `ChannelBank.Overloaded` holds every gate shut for the duration — a transmitter close enough to desense the receiver (the operator's own beacon) otherwise opens the whole band at once. Gates already open keep their clip; they were real before the overload hit. On the way out, re-reference every *closed* channel's floor in one block — never an open one, which would cut a transmission off mid-over. Levels alone cannot tell you this; the hardware can.
- **The overload report lags the overload.** `sdrplay_api_PowerOverloadChange` arrives after the ADC is already clipping, so gates opened in the half-second before it are part of the same event and are disowned retroactively (discarded, never posted). Gates stay shut for a guard period after the *clear* too — the front end does not recover instantly, and a gate opened into that transient latched for 49 s on air. Floor re-seeding after an overload may only pull floors **down** (`Math.Min`): adopting the current level outright blinds any channel that happens to be transmitting when the guard expires.
- **A gate that never closes is not a transmission.** The max-open safety valve measures from the hop the *gate* opened (`GateOpenedHop`), never from the clip start — clip rollover starts a new `ActiveTransmission`, so a valve keyed on clip start resets every 90 s and never fires. On force-close, re-seed that channel's noise floor from its current level: the floor is frozen while a gate is open, so a latched channel is by definition sitting above a stale floor and will re-latch on the next block otherwise. Both are covered by `PersistentCarrierIsForceClosedOnceAndDoesNotRelatch`.
- **Squelch decides in *relative* space.** Gate thresholds compare each channel against the band median, never absolute dBFS: the RSP's AGC steps every channel's gain at once, and absolute-level squelch latches every gate open when it does. Audio level is likewise deviation-referenced (FM is constant-envelope — RF AGC has no effect on demodulated loudness) with a soft limiter so over-deviating stations compress instead of clipping.
- **Squelch tones are read, then filtered.** CTCSS (67–254 Hz) and DCS (a 134.4 bps sub-audible bitstream) sit below the voice, and 750 µs de-emphasis is flat below its 212 Hz corner while rolling voice off above it — so untouched they arrive *louder* than the speech (measured: 55–76% of recorded energy). `SubaudibleDetector` taps the discriminator **before** the 300 Hz audio high-pass, because that filter exists to discard exactly what it reads; anything added to the audio chain must stay downstream of the tap. Detection costs 0.113% of one core per open gate (3.6% with all 32 open), so it runs on **every** transmission unconditionally — never gated on whether a channel already has a tone configured, because the interesting cases are the mismatches: a transmission with no tone on a channel that normally has one is someone with their tone switched off, and a different tone is a different system sharing the frequency. The measured tone is persisted per transmission and learned onto the channel (`ChannelLearnedState.CtcssToneHz`) — two repeaters commonly share an output frequency and the tone is what tells them apart. Never round a measured frequency onto the standard tone table without a confidence check: a mains hum is not the nearest CTCSS tone. A tone is accepted only if it beats its runner-up, beats guard bins 1.2 Hz either side of itself, **and** holds a real share of sub-audible energy — all three, because each alone admits something (a DCS bitstream is peaky, plain speech has margin). CTCSS and DCS are alternative systems, never both: a tone beating against the 134.4 bps bit clock produces a repeating, Golay-valid phantom code, which is how 146.640 (CTCSS 146.2) reported DCS 073.
- **Model pre-emphasis when testing sub-audible DSP.** Transmitters pre-emphasise voice +6 dB/octave but inject CTCSS/DCS *after* that stage, so at the discriminator the voice's low end is ~20 dB below its raw level. A fixture that omits this makes the sub-audible band look far dirtier than air: tuned against it, 21 of 83 DCS codes decoded as the *wrong* valid code. Equally, a fixture whose speech has nothing below 300 Hz makes every threshold look safe — the pitch fundamental sits inside the CTCSS range and wanders, and that is the real thing a tone must be told apart from.
- **CTCSS 179.9 Hz is indistinguishable from 60 Hz mains' third harmonic** (0.1 Hz apart) inside one over. Do not write tests that demand otherwise.
- **Audio is ground truth.** Clips are Opus/OGG at 16 kHz, 32 kbps VBR voice mode. Every transcript/embedding row records the model name + version that produced it so results can be reprocessed when models improve.
- **A net occurrence is one session, and the declared window is its boundary.** A net is a conversation with long pauses — check-ins trickle in, control waits, someone goes to look something up — so the 90 s join gap that works for a ragchew shreds it: observed on 144.920, one three-hour net became **nineteen** sessions in an afternoon, with gaps up to fifteen minutes between overs. Inside a declared window the window itself is the boundary and the gap rule does not apply (`NetSchedule.TryGetWindow` returns the occurrence's start, which is its identity — the *window that opened*, so a net running past UTC midnight does not split there either). This is not cosmetic: sessions are the unit summaries are written for, so fragmenting a net turns one useful summary into nineteen summaries of two transmissions each, and the net's "occurrences" count becomes a count of fragments.
- **A capped work query must filter before it caps, not after.** `SummaryCandidates` decides eligibility — a net always, a ragchew only past `MinRagchewMinutes` — inside the query. Applying the rule after a `Take(n)` starves the queue outright: the page fills with sessions that are then all discarded, they never gain a summary so they are still candidates next pass, and the same rejected page is fetched forever while everything behind it waits. Measured, this meant **no session was ever summarised**, with no error anywhere to say so. Order newest-first for the same reason: when there is more work than one pass can take, serve the backlog the operator is actually looking at. Note the duration test is written as a shifted end (`EndUtc.AddMinutes(-n) >= StartUtc`) because SQLite's provider cannot translate `EndUtc - StartUtc`, and a silent fall back to client evaluation would be this same bug in a new place.
- **Tell the summariser how much to write, scaled to what was said.** The facts come from code and the model only writes prose from them — but *how much* prose is the prompt's job, and a fixed "concise, 3-6 sentences" fails in the direction nobody notices: measured, a 41-transmission session with 8,700 characters of transcript came back as two sentences, a 35:1 compression that discarded almost everything. `SummaryPrompt.LengthGuidance` scales the ask with the transcript, `MaxTokens` scales with it too (a fixed ceiling truncates exactly the long sessions that needed room), and the prompt names what to cover with a worked example, because a model asked only for "a summary" returns one sentence about topics and stops. A 1.5B model still under-delivers on multi-paragraph asks; that is a model-size limit, not a prompt bug.
- **Deterministic before LLM.** Facts (check-in rosters, net control, schedules, durations) come from code over the database. The local LLM only writes narrative prose from those facts.

## .NET / EF Core

- EF Core models live in the `SignalScribe.Data.Models` namespace under `SignalScribe/Data/Models/`
- `SignalScribeContext` lives in the `SignalScribe.Data` namespace at `SignalScribe/Data/`
- Enums live in the `SignalScribe.Enums` namespace under `SignalScribe/Enums/`
- Each entity implements `IEntityTypeConfiguration<T>` directly on itself (not a nested class); the `Configure` method holds all fluent API config for that model
- Do not add fluent API calls directly in `OnModelCreating`
- The `DbContext` discovers all configs by scanning the assembly: `modelBuilder.ApplyConfigurationsFromAssembly(typeof(SignalScribeContext).Assembly)`
- JSON columns (e.g. per-channel learned state, model metadata) are stored as `string` / `string?` in the database; the entity exposes a typed, deserialized property and handles serialisation/deserialisation itself — callers always work with the typed value, never the raw JSON string
- All `DateTime` properties are UTC (capture-side timestamps derive from the SDR sample counter anchored to NTP-synced wall clock once per stream — never per-event wall clock reads). Net schedules are stored in UTC too (day-of-week + time-of-day columns); **the browser converts to/from local time for display and entry** — no timezone data server-side
- Service status streams over SignalR: capture/workers are SignalR *clients* pushing `ServiceStatusUpdate`s to the `/hubs/status` hub; the hub keeps latest-per-service **in memory only** (never the database — daemons re-push on reconnect) and broadcasts to browser clients
- **Operator settings live in the DB, not appsettings**: single-row entities (`CaptureSettings`, `WorkerSettings`, Id=1, seeded by migration), edited via `api/v0/settings`, fetched by daemons via `api/internal/settings`, change-notified via `settingsChanged` on the status hub (daemons re-fetch and apply live). appsettings/env carries only deployment config (paths, host URL, source selection) and unreachable-host fallbacks. Capture distinguishes disruptive settings (frequency/rate/spacing ⇒ pipeline rebuild, close clips gracefully) from live-apply (gain/AGC/squelch)
- Use controllers for all API endpoints — do not use minimal API (`app.MapGet` / `app.MapPost` etc.)
- All UI-facing controllers use the route prefix `api/v0/` — the `v0` prefix signals this is an unsupported UI-only API surface; the sole exception is `HealthController` which stays at `/health`. Internal daemon/worker endpoints (event ingest, job queue) use `api/internal/`
- Controller request/response models (DTOs) live in `SignalScribe.Api/Controllers/Models/` under the namespace `SignalScribe.Api.Controllers.Models` — keep models in that folder, not in a separate `Contracts/` directory
- `appsettings.local.json` is git-ignored and always loaded as an optional override file — use it for local paths or overrides

## DSP conventions

- Hot paths use `Span<T>` / `Vector<T>` / `System.Runtime.Intrinsics`; no allocations inside the sample loop
- **One symbol synchroniser serves every digital mode.** `SymbolSynchronizer` is a Gardner timing loop on the discriminator, and Gardner is blind to symbol *values* — so two-level D-STAR and four-level C4FM share it unchanged. It does timing only: slicing, normalisation and interpretation differ per mode and belong to the framers. Two details there were each worth a debugging session and must not be "simplified" away: the interpolation is **cubic**, because at 5.2 samples per symbol a straight line leaves a phase-dependent error the loop cannot distinguish from a real clock offset (a 100 ppm transmitter read as 800); and the loop gains sit near critical damping (Ki ≈ Kp²/4), because an over-driven integrator wanders and leaves standing jitter that a two-level eye hides and four-level does not — measured at 7% symbol errors before it was damped.
- The capture daemon must support an IQ-file replay source interchangeable with the RSP1 source; DSP changes need replay-based regression coverage
- Per-channel learned state (noise floor, courtesy-tone signature, repeater/simplex classification) is persisted via the host API, not kept only in memory
- Handle the SDRPlay service wedging: detect a stalled sample counter, tear down, re-init. Log ADC overload counts

## Vue / Frontend

- All Axios HTTP calls are made through TypeScript classes located in `src/api` — no Axios requests outside of this directory
- All API files import the shared Axios instance from `src/api/axios.ts` — do not call `axios.create` in individual API files; add interceptors or shared config in `axios.ts`
- CORS is never needed and must never be added — in development the Vite dev server proxies `/api`, `/swagger`, and `/hubs` to `http://localhost:5020`; in production the API serves the built frontend as static files, so all requests are same-origin
- State that is only used within a single component or class stays local; only reach for Pinia when sharing state across components or classes
- Use Vuetify for all UI components
- Path alias `@` resolves to `src/`
- Formatting is handled by `oxfmt`; linting by `oxlint` then `eslint` — run `npm run lint` before committing

## Testing

- Every new DSP path (channel type handled, segmentation marker, demod branch) must have a replay-based regression test in `SignalScribe.Tests` driven by a checked-in or generated IQ fixture
- Every new parsing/analysis path (phonetic→callsign normalization case, net-detection heuristic, marker interpretation) must have a corresponding unit test
- Logic that can be extracted as pure functions (segmentation decisions, callsign normalization, recurrence mining) belongs in static helper classes so it can be tested without constructing the full background service
- Use an in-memory SQLite database (via `SqliteConnection("DataSource=:memory:")` + `DbContextOptionsBuilder.UseSqlite`) for tests that exercise DB-level logic — do not use the EF Core in-memory provider, as it does not enforce SQL translation constraints
- Run `dotnet test SignalScribe.Tests/SignalScribe.Tests.csproj` before committing; all tests must pass
